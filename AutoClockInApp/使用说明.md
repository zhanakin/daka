# Android 自动打卡助手 · 使用说明

这是一个完整的 Android Studio 工程源码（Kotlin），编译安装后可在手机上独立运行：到点自动打开企业微信，查找打卡按钮并点击。

> **合规提醒**：请仅用于你本人、在你有权限的设备上做合规考勤辅助。不要用它伪造定位、绕过人脸/活体核验、代他人打卡或违反公司制度。使用无障碍服务涉及较高系统权限，请谨慎。

## 2. 编译环境

- Android Studio（建议 2024.2 或更新版本）
- JDK 17
- Android SDK Platform 35（打开工程后 Studio 会提示安装）
- Gradle 8.9（由 wrapper 自动下载）

## 3. 导入与编译

1. 打开 Android Studio → `File > Open` → 选择 `AutoClockInApp` 目录。
2. 等待 Gradle Sync 完成。若提示缺少 Gradle wrapper 脚本，可在 Studio 中执行 `File > Gradle Wrapper` 生成完整 wrapper；日常使用不需要命令行。
3. 用数据线连接手机（手机开启「开发者选项 → USB 调试」），确认 Studio 识别到设备。
4. 点击工具栏 `Run`（绿色三角）直接安装到手机；或执行 `Build > Build Bundle(s)/APK(s) > Build APK(s)`。
5. Debug APK 输出位置：`app/build/outputs/apk/debug/app-debug.apk`，可手动传到手机安装。

## 4. 手机端设置（首次必做）

1. 安装并登录企业微信，至少手动进入一次打卡页面。
2. 打开「自动打卡助手」App，设置目标时间（如 09:00）。
3. 点击「打开无障碍设置」，在系统列表中找到 **自动打卡助手**，开启权限。系统通常会弹确认框，选择允许。
4. **Android 12 及以上**：点击「检查精确闹钟权限」，在系统设置里允许本应用设置闹钟和提醒。
5. 勾选「启用每日自动打卡」。此时 AlarmManager 已设定每日闹钟。
6. 建议先点「立即测试一次」，盯着手机看是否会自动打开企业微信并点击按钮。

## 5. 工作原理

- `AlarmScheduler` 用 `AlarmManager.setExactAndAllowWhileIdle` 设定每日闹钟，低电耗模式下也能触发。
- 闹钟触发 `ClockInReceiver`，它申请 `PARTIAL_WAKE_LOCK` 唤醒 CPU，再发站内广播。
- 已开启的无障碍服务 `AutoClockInService` 收到广播后：
  1. 通过 `PackageManager` 拉起企业微信；
  2. 延迟 2 秒等待页面加载；
  3. 遍历当前窗口控件树，查找文字或 content-desc 含「打卡」且可点击的节点；
  4. 优先 `performAction(ACTION_CLICK)`，否则用 `GestureDescription` 在节点中心模拟点击；
  5. 最多重试 4 次，每次间隔 1.5 秒；结果写入本地并显示在 App 首页。
- 开机后 `BootReceiver` 会按保存的时间重新设定闹钟。

## 6. 常见修改点

| 想改什么 | 改哪里 |
| --- | --- |
| 企业微信包名 | `AutoClockInService.kt` 中的 `WECOM_PACKAGE` |
| 匹配按钮的文字规则 | `AutoClockInService.kt` 中 `findClockInNode()` 的 `contains("打卡")` |
| 重试次数和间隔 | `AutoClockInService.kt` 中的 `MAX_ATTEMPTS`、`ATTEMPT_DELAY_MS` |
| 默认打卡时间 | `Prefs.kt` 中 `hour` / `minute` 的默认值 |
| 只监听企业微信的事件 | `res/xml/accessibility_service_config.xml` 的 `android:packageNames` |

## 7. 常见问题

- **提示未找到打卡按钮**：确认企业微信已停留在打卡页面；不同企业可能显示「上班打卡 / 下班打卡 / 外勤打卡」，当前规则已用 `contains("打卡")` 覆盖。若企业微信页面是 Flutter/自绘渲染，控件树里可能没有文字，本版本无法定位，需要再加图像识别兜底。
- **无障碍服务显示已开启但不点击**：用 Android Studio 的 Logcat 过滤标签 `AutoClockIn` 看日志；确认服务已打印“无障碍服务已连接”。
- **闹钟到点不触发**：确认已授予精确闹钟权限；关闭电池优化或把本应用设为「不受限制」；国产 ROM（MIUI/EMUI/ColorOS）还需允许自启动和关联启动。
- **手机重启后失效**：检查 `BootReceiver` 是否被 OEM 系统禁用了「开机自启」；本应用依赖 `RECEIVE_BOOT_COMPLETED`。
- **锁屏/休眠问题**：闹钟使用 `RTC_WAKEUP` 并持有 WakeLock，CPU 会唤醒；但如果锁屏有密码/图案，仍需先解锁。可考虑让手机停留在打卡页面并关闭自动锁屏。
- **安装失败**：检查是否用了不同签名覆盖安装；先卸载旧版再装。

## 8. 不装 Android Studio 的编译方式

### 方式 A：GitHub Actions 云编译（本地完全不装软件）

工程里已包含 `.github/workflows/build.yml`，云端会自动装 JDK、Android SDK 和 Gradle，编译后产出 APK。

1. 在 GitHub 新建一个空仓库（Public/Private 均可）。
2. 把 `AutoClockInApp` 目录里的全部文件（包含隐藏的 `.github` 目录）上传到仓库。
3. 进入仓库的 `Actions` 页签，找到 `Build Android APK`，点击 `Run workflow`。
4. 等待运行结束后，在本次运行页面底部下载 `app-debug` 工件，解压得到 `app-debug.apk`。
5. 把 APK 传到手机安装即可。

> 也可以直接 `git push` 到 `main`/`master` 分支，每次推送都会自动编译。

### 方式 B：只用命令行工具（下载量比 Android Studio 小很多）

不装 IDE，只装三样东西：JDK 17、Android command-line tools、Gradle 8.9。大概几百 MB，而不是 Android Studio 的 1GB+。

Windows PowerShell 示例（需先自行安装 JDK 17 并配置好 `JAVA_HOME`）：

```powershell
# 1. 下载 Android 命令行工具（约 130MB），解压到 C:\android-sdk\cmdline-tools\latest
#    下载地址：https://developer.android.com/studio#command-line-tools-only

# 2. 接受许可并安装编译所需组件
$env:ANDROID_HOME = "C:\android-sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --licenses
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --install "platforms;android-35" "build-tools;35.0.0"

# 3. 在工程目录生成 Gradle wrapper 并编译
gradle wrapper --gradle-version 8.9
.\gradlew.bat assembleDebug
```

产物在 `app\build\outputs\apk\debug\app-debug.apk`。

### 方式 C：手机上直接编译（Termux，进阶）

手机安装 Termux（小体积终端 App），在 Termux 里装 `openjdk-17`、Android command-line tools 和 Gradle，也能编译，但依赖 aarch64 包支持，配置较繁琐，仅作为没有电脑时的备选。

---

推荐优先用 **方式 A**：本地零安装，点几下就能拿到 APK。
